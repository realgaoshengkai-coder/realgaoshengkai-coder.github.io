Codex Native · Parallel Divergent Ideation

让不同思路先彼此不知道，再认真收敛。

一个问题先进入多个隔离认知视角；所有分支返回后，独立 critic 才开始聚类、评分、排除陷阱，并并行深化最值得做的方向。

Method → Codex adaptation

先扩展搜索空间，再用阶段屏障收敛。

01 / 核心流程

隔离发散，独立批评。

多个认知框架互不共享上下文地生成候选；全部返回后，独立 critic 才开始评分、聚类、排除陷阱并选出继续深化的方向。

02 / 这版加强

把方法绑定到 Codex 任务树。

root 直接调度 frame、critic 与 focus Agent；每个分支使用 fork_turns="none" 隔离上下文，整批 dispatch 后设置阶段 barrier，并用稳定任务名保留拓扑。

03 / 更 Codex Native

不用外部编排器模拟 Codex。

生成、等待、状态收集和并行深化直接映射到 Codex collaboration primitives；idea 是 frame 返回的记录，而不是额外子线程，因此保留发散宽度，又尊重 Codex 的线程池。

来源：我为什么要改原版
原版验证了“隔离视角发散、独立 critic 收敛”的价值，但跨 Agent Skill、CLI 与 Node library 的编排没有利用 Codex 已有的任务树、上下文隔离和阶段等待能力。我保留方法，把运行方式重写为 Codex collaboration primitives，让发散、收敛和状态都留在同一个 Codex 任务中。
原版：ADHD by UditAkhourii（MIT）↗

Upstream → Codex Native

与原版的 21 项完整差异。

对照基于原版 eaeba4e。没有列出的核心方法保持不变。

维度原版 ADHDADHD Codex

名称与触发

原版 ADHD

adhd、/adhd、ADHD mode

ADHD Codex

adhd-codex、$adhd-codex、/adhd-codex、ADHD Codex mode

产品载体

原版 ADHD

跨 Agent Skill；另有 Claude Agent SDK 驱动的 Node/TS library 与 CLI

ADHD Codex

Codex 插件中的单一 Skill；不封装上游 Node runtime

编排原语

原版 ADHD

Skill 使用通用 Agent/Task 表述；library 使用 Claude Agent SDK、p-limit

ADHD Codex

直接使用 collaboration.spawn_agent、wait_agent、list_agents

任务拓扑

原版 ADHD

要求分支隔离，但不规定必须是 root 的直接子任务

ADHD Codex

frame、critic、focus 全部是 root 的直接子任务；正常运行只占一层 spawned depth

上下文隔离

原版 ADHD

通用 fresh context / isolated process

ADHD Codex

每个子任务明确使用 fork_turns="none"，只传问题、必要上下文和本阶段输入

阶段同步

原版 ADHD

Skill 要求 Phase 1 完成后再收敛；library 用 Promise.all

ADHD Codex

每一阶段先整批 dispatch，再等待所有任务 terminal；未过 barrier 不启动下一阶段

任务命名

原版 ADHD

未规定可追踪命名

ADHD Codex

固定使用 frame_<id>、critic_<stage>、focus_<rank>

idea 的承载方式

原版 ADHD

library 为带 UUID 的 Idea 对象；Skill 未限定任务粒度

ADHD Codex

每个 frame Agent 一次返回该框架的 idea records，不为每条 idea 再开子任务

默认规模

原版 ADHD

Skill 默认 5 × 6；library 默认 framesPerRun=5、ideasPerFrame=6、topK=3

ADHD Codex

固定 5 × 8，最终深化 Top 3

Quick

原版 ADHD

原版只在 calibration 中建议按任务规模调整，没有独立 mode token

ADHD Codex

显式 quick / 快速：3 × 4，深化 Top 1

Deep

原版 ADHD

没有专门的全框架模式

ADHD Codex

显式 deep / 深入：15 个内置 frame 各 4 条，去重聚类后深化 Top 3

问题重写

原版 ADHD

Node engine 默认先执行 strip-anchors reframe pass

ADHD Codex

没有额外模型重写阶段；保留用户问题，只由 pre-flight 判断是否适合发散

critic 顺序

原版 ADHD

Node engine 在分支返回后并行 score 与 cluster；Skill 可在当前 orchestrator 内收敛

ADHD Codex

先用独立 critic consolidate，再用新的 critic score；生成 Agent 不参与评判

语义去重

原版 ADHD

原版 cluster，但没有 deep 专用的 provenance-preserving dedupe 合同

ADHD Codex

Deep 先合并语义重复项，保留最佳措辞和全部来源 frame，再聚类

评分与选择

原版 ADHD

novelty 35% + viability 40% + fit 25%；shortlist 2 至 4，并标记 non-obvious pick

ADHD Codex

Default/Quick 保留同一权重；Deep 改用 relevance、actionability、information gain、diversity，并逐项重算 diversity

并发策略

原版 ADHD

Node engine 以 p-limit 控制，默认 concurrency 4，可配置

ADHD Codex

每阶段全量并行；Deep 需要 15 个可用 frame slots，不足时报告容量而不是在 root 中假装并行

输出

原版 ADHD

常规输出 wide set、shortlist、traps、focus、provocation；library 返回结构化 RunResult

ADHD Codex

Default/Quick 保留完整展示；Deep 只显示 Top 3、合并数量、来源 frame、风险和第一步，不倾倒 60 条池

进度信号

原版 ADHD

Node library 提供 onEvent 回调

ADHD Codex

依赖 Codex 任务树和 terminal 状态；没有独立事件 API

结构校验与恢复

原版 ADHD

Node engine 使用 Zod、UUID 和 parse fallback

ADHD Codex

当前是 Skill orchestration contract；要求 JSON 输出，但尚未内置 Schema 校验、run ID、自动重试或失败恢复

依赖与批处理

原版 ADHD

可安装 adhd-agent CLI/library，依赖 Claude Agent SDK、p-limit、Zod

ADHD Codex

Skill 自身无外部 runtime 依赖，也不提供独立 CLI 或 batch API
