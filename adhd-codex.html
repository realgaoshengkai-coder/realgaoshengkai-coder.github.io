一个问题先进入多个隔离认知视角；所有分支返回后，独立 critic 才开始聚类、评分、排除陷阱，并并行深化最值得做的方向。

Method → Codex adaptation

先扩展搜索空间，再用阶段屏障收敛。

01 / 核心流程

隔离发散，独立批评。

多个认知框架互不共享上下文地生成候选；全部返回后，独立 critic 才开始评分、聚类、排除陷阱并选出继续深化的方向。

02 / 这版加强

把方法绑定到 Codex 任务树。

root 直接调度 frame、critic 与 focus Agent；每个分支使用 fork_turns="none" 隔离上下文，整批 dispatch 后设置阶段 barrier，并用稳定任务名保留拓扑。

03 / 更 Codex Native

不用外部编排器模拟 Codex。

生成、等待、状态收集和并行深化直接映射到 Codex collaboration primitives；idea 是 frame 返回的记录，而不是额外子线程，因此保留发散宽度，又尊重 Codex 的线程池。

来源：我为什么要改原版
原版验证了“隔离视角发散、独立 critic 收敛”的价值，但跨 Agent Skill、CLI 与 Node library 的编排没有利用 Codex 已有的任务树、上下文隔离和阶段等待能力。我保留方法，把运行方式重写为 Codex collaboration primitives，让发散、收敛和状态都留在同一个 Codex 任务中。
